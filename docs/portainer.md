# Tunnelwright Panel AWG в Portainer (NAS)

На NAS работает только панель (`panel-api` + `web`). VPN — на удалённых нодах (VPS): панель ставит
их по SSH, обновляет агентов сама и собирает их данные в бэкапы. Модули ядра, TUN и проброс UDP на
NAS не нужны. Требования: Docker с Portainer, процессор amd64 или arm64.

## Установка

1. **Образы.** `ghcr.io/prg77/tunnelwright-api` и `tunnelwright-web` публичные — Portainer скачает их сам.
   Для форка с приватными пакетами: Registries → Add registry → Custom, `ghcr.io`, логин GitHub
   и токен с правом `read:packages`.
2. **Стек.** Stacks → Add stack → Web editor, вставьте [`deploy/portainer/docker-compose.yml`](../deploy/portainer/docker-compose.yml)
   (или Repository с этим путём). Переменные в Environment variables:

   | Переменная | По умолчанию | Назначение |
   |---|---|---|
   | `WEB_PORT` | `58821` | Порт панели на NAS |
   | `PANEL_HOST` | — | Адрес панели снаружи (DDNS-имя или IP): сертификат, уведомления |
   | `PANEL_TLS` | `on` | `on` — HTTPS с самоподписанным сертификатом; `off` — HTTP за обратным прокси |
   | `PANEL_PUBLIC_URL` | `https://PANEL_HOST:WEB_PORT` | Адрес за обратным прокси (ссылки пользователей из Telegram-бота) |

3. **Первый вход.** Containers → `tunnelwright-api` → Logs: строка «Создан администратор» с логином и
   паролем. Войдите на `https://<NAS>:58821` и смените пароль в «Настройки → Безопасность».
4. **Ноды.** «Ноды → Добавить»: адрес VPS и пароль root или ключ SSH. Панель подключается к ноде сама,
   входящие соединения на NAS не нужны.

Забыли пароль: Containers → `tunnelwright-api` → Console → `python -m app.cli reset-admin`.

## Доступ снаружи: обратный прокси NAS

Самоподписанный сертификат подходит для панели. Для ссылок пользователей (`/u/…`) удобнее настоящий
сертификат — через обратный прокси NAS с Let's Encrypt (Synology: Панель управления → Портал входа →
Дополнительно → Обратный прокси; QNAP: Network & File Services → Reverse Proxy):

- в стеке: `PANEL_TLS=off`, `PANEL_PUBLIC_URL=https://vpn.example.com`;
- в прокси: источник `https://vpn.example.com:443` → назначение `http://localhost:58821`.

В режиме `off` панель доверяет `X-Forwarded-For` и `X-Forwarded-Proto` от прокси из локальной сети
(10/8, 172.16/12, 192.168/16) — порт `WEB_PORT` не пробрасывайте на роутере напрямую.

## Перенос панели с VPS на NAS

1. На старой панели: «Настройки → Резервные копии → Сделать бэкап сейчас», скачайте архив.
2. На NAS: «Настройки → Резервные копии → Восстановить из бэкапа» — архив и его пароль. Панель
   перезапустится; войдите с логином и паролем из бэкапа.
3. Ноды, установленные старой панелью, принимают запросы только с её IP. На каждой ноде:
   «Ноды → Обновить» (по SSH) — агент переустановится без привязки к IP, клиенты и ключи сохранятся.
4. VPN, который работал на сервере старой панели («Этот сервер»), на NAS не переносится: его клиенты
   остаются в панели с профилями на удалённых нодах.

## Обновление

Стек всегда берёт последний релиз (`latest`) — те же образы, что и установка на сервер, отдельных
версий для NAS нет. Обновить: Stacks → tunnelwright → Update the stack с «Re-pull image». Агентов
нод панель обновит сама до своей версии.
Данные — в томах `tunnelwright_data` и `tunnelwright_tls`, при обновлении не теряются.

## Чем отличается от установки на сервер

| | `install.sh` на сервере | Portainer на NAS |
|---|---|---|
| VPN на сервере панели | по выбору | нет |
| Сертификат | хост, systemd-таймер | контейнер `web` (или прокси NAS) |
| Пароль администратора | установщик | лог `tunnelwright-api` при первом запуске |
| Обновление | `tunnelwright update` | Portainer, Re-pull image |
| Восстановление | `tunnelwright restore` | «Настройки → Резервные копии» |
| Привязка нод к IP панели | да | нет (`PANEL_NODE_IP_LOCK=false`): токен и TLS с закреплённым сертификатом |
