# Tunnelwright Panel AWG — архитектура

## Назначение

Панель управляет несколькими VPN-нодами на AmneziaWG (wg-easy): клиент создаётся один раз и
получает профиль с тем же IP на каждой ноде. Панель — источник правды, агенты нод выполняют.

## Компоненты

```
браузер ──HTTPS──► web (nginx: React + TLS, самоподписанный сертификат)
                    └─ /api/*  ─► panel-api        [контейнер, сеть tunnelwright, без портов наружу]
                                    ├ SQLite /data/panel.db
                                    ├ фоновые задачи (трафик, сроки, квоты, бэкапы, бот)
                                    └─ HTTP + токен ─► node-agent (на каждой ноде)

нода (сейчас — тот же сервер):
  wg-easy 15.5.0  [AmneziaWG userspace, API только во внутренней сети]
  node-agent      [контейнер в сетевом namespace wg-easy: network_mode service:wg-easy, NET_ADMIN]
```

| Компонент | Образ | Ответственность |
|---|---|---|
| `web` | `ghcr.io/prg77/tunnelwright-web` | статика React, TLS, прокси `/api/*` → panel-api, страница пользователя `/u/<токен>` → panel-api |
| `panel-api` | `ghcr.io/prg77/tunnelwright-api` (Python 3, FastAPI) | вход и сессии, 2FA, клиенты, группы, списки, WireSock, GeoIP, портал, трафик, квоты, Telegram, бэкапы, журнал, настройки, реестр нод |
| `node-agent` | `ghcr.io/prg77/tunnelwright-node` (Python 3) | адаптер к API wg-easy, tc-лимиты, метрики ноды, health; API с токеном |
| `wg-easy` | `ghcr.io/wg-easy/wg-easy:15.5.0@sha256:…` | WireGuard/AmneziaWG, ключи, конфиги, сроки клиентов (`expiresAt`) |

Наружу открыты только порт панели (HTTPS) и UDP-порт VPN. Веб-интерфейс wg-easy недоступен снаружи.

## Проверено на сервере (wg-easy 15.5.0)

- AmneziaWG работает в userspace (`amneziawg-go`) без модуля ядра. Нужны
  `--device /dev/net/tun`, `EXPERIMENTAL_AWG=true`, `OVERRIDE_AUTO_AWG=awg`.
- `DISABLE_IPV6=true` обязателен на ядрах без `ip6_tables` (IPv6 NAT не поднимается).
- API: Basic-auth логином администратора wg-easy, без входа — честный 401.
- Параметры AmneziaWG (`Jc…H4`) задаются через `POST /api/admin/interface`.
- Встроенный healthcheck образа вызывает `wg show` и с AmneziaWG падает — переопределяем на `awg show`.
- Клиентский конфиг по умолчанию содержит IPv6 (DNS, `::/0`) и `PersistentKeepalive = 0` —
  выставляем через `admin/userconfig`.

## Авторизация

- `panel-api` ведёт своих администраторов: логин, хэш пароля (argon2), TOTP 2FA,
  лимит попыток входа по IP, сессии в cookie (`Secure`, `HttpOnly`, `SameSite=Strict`).
- Пароль текущей панели при переносе становится паролем администратора `admin`.
- Учётка администратора wg-easy генерируется случайно, хранится только у `node-agent`
  (файл с правами 600). 2FA на ней не включается — иначе API wg-easy не работает.
- `panel-api` ↔ `node-agent`: токен ноды в заголовке. Для удалённых нод — HTTPS с
  закреплённым отпечатком сертификата агента.

## Данные (panel.db)

`admins`, `sessions`, `audit_log`, `settings` (имя панели, часовой пояс, Telegram, бэкапы),
`nodes`, `clients` (связь с `node_id` + id клиента в wg-easy, группа, заметка, квота),
`groups`, `speed_limits`, `traffic_daily`, `traffic_points`, `lists`, `list_items`,
`client_routing`, `portal_tokens`, `portal_template`, `tg_admins`.

Срок действия клиента хранит wg-easy (`expiresAt`), панель только задаёт его.

## Фоновые задачи panel-api

| Задача | Период | Что делает |
|---|---|---|
| traffic | 60 с | опрос нод, суточные суммы и точки графика (по часовому поясу настроек) |
| quotas | 5 мин | превышение квоты → отключить клиента, уведомить; 80 % → предупредить |
| expiry | 5 мин | уведомление о скором истечении (отключает сам wg-easy) |
| health | 2 мин | доступность нод и wg-easy, уведомления без повторов |
| backup | по расписанию | архив `wg-easy.db` + `panel.db`, шифрование паролем бэкапа, отправка админу в Telegram |
| bot | long polling | команды администратора в Telegram |

## HTTPS

Самоподписанный сертификат генерирует установщик (`openssl`, срок 1 год, SAN = IP/хост).
Таймер systemd раз в сутки проверяет срок и за 30 дней до истечения перевыпускает
сертификат и перезагружает nginx. HTTP на порту панели отвечает редиректом на HTTPS.

## Версии (закрепляются)

wg-easy 15.5.0 (по digest), nginx stable, Node LTS для сборки UI, Python 3 для API,
зависимости — lockfile (`package-lock.json`, `requirements.lock`), Renovate для обновлений.

## Несколько нод

```
панель ──HTTPS :8711 (токен + закреплённый сертификат)──► node-agent ноды
       ──SSH (только при установке/обновлении)──────────► нода
```

- Нода — отдельный сервер с `wg-easy` и `node-agent` в каталоге `/opt/tunnelwright-node`
  (compose-проект `tunnelwright-node`). Панель на ноде не ставится.
- Установка из панели: адрес, SSH-порт, пользователь root и пароль или приватный ключ.
  Учётные данные используются один раз и не сохраняются; отпечаток SSH-ключа хоста
  запоминается и сверяется при обновлении ноды.
- Скрипт установки (Debian/Ubuntu) ставит Docker, создаёт токен ноды и самоподписанный
  сертификат агента (10 лет), поднимает wg-easy и агент, открывает в ufw UDP-порт VPN и
  порт агента — только для IP панели. Образ агента берётся из GHCR, если пакет публичный,
  иначе собирается на ноде из исходников, которые панель передаёт по SSH.
- Панель хранит URL агента, токен и сертификат ноды (доверяет только ему — проверка
  имени хоста не нужна). Ключи VPN-клиентов остаются на ноде.
- Повторный запуск установки на той же ноде — обновление: данные, токен и сертификат сохраняются.
- Удаление ноды: «только из панели» (сервер не трогается) или «удалить с сервера» по SSH —
  контейнеры, их данные, образы и правило ufw; Docker остаётся. Запись ноды убирается после успеха.
- Бэкап панели содержит данные всех доступных нод (недоступная пропускается, а не роняет бэкап).
  Переустановленный сервер ноды: «Обновить» с отметками «сервер переустановлен» (принять новый ключ
  SSH-хоста) и «восстановить из бэкапа» — нода получает прежние ключи, клиентам не нужны новые конфиги.
  `tunnelwright restore` восстанавливает панель и VPN её сервера (если он включён); удалённые ноды
  хранят свои данные сами.

## Клиент на всех нодах

- Клиент — сущность панели (`clients`: имя, IP, включён, срок, группа, метаданные).
  На каждой ноде у него профиль (`profiles`: нода + id клиента в wg-easy) со своими ключами
  и **тем же IP** — поэтому лимиты скорости (по IP) одинаковы на всех нодах и хранятся в панели.
- Панель — источник правды. Синхронизация ноды (раз в минуту и после каждого изменения)
  создаёт недостающие профили (новая нода, нода была недоступна), выравнивает имя, IP,
  состояние, срок и лимиты, удаляет профили удалённых клиентов (удалённый клиент помечается
  и окончательно исчезает, когда его профили убраны со всех нод). Клиент, найденный на ноде
  без профиля в панели, принимается в панель (по IP — привязывается к существующему).
- У клиента есть скрытый постоянный ID (`uid`, 8 hex). Имена могут повторяться — ID нет.
  Агент ноды хранит связь «клиент wg-easy → uid» (`/data/uids.json`), поэтому профиль
  привязывается к своему клиенту по ID даже после восстановления бэкапа или повторного
  добавления ноды; IP используется только для профилей без ID.
  ID виден в интерфейсе у одинаковых имён, работает в поиске и в боте (`/client #a1b2`).
- Трафик и квота считаются по сумме профилей; конфиг, QR и страница пользователя — отдельно
  для каждой ноды.
- VPN на сервере панели необязателен: новые установки — без него (`--no-local-vpn`),
  `tunnelwright local-vpn on|off` переключает. Без локальной ноды дашборд показывает нагрузку
  сервера панели, а VPN-серверы добавляются в разделе «Ноды».

## Интерфейс

- Стиль Grafana: боковое меню слева (разделы «VPN» и «Администрирование», сворачивается до иконок),
  шапка с хлебными крошками и живой сводкой, плоские панели, шрифт Inter 14 px.
- Две темы — тёмная и светлая — с одинаковой функциональностью, переключаются в шапке.
  Цвета заданы токенами в `web/src/theme/tokens.css` (палитра Grafana), компоненты используют
  только CSS-переменные; графики — классическая палитра Grafana, одинаковая в обеих темах.

## Автообновление нод

Агенты удалённых нод догоняют версию панели сами, без SSH. При проверке нод (сразу после старта
панели и раз в 2 минуты) отстающая нода получает `POST /update?version=…` с архивом исходников
агента. Агент только записывает запрос в `/opt/tunnelwright-node/update` (смонтирован в контейнер);
systemd-юнит `tunnelwright-node-update.path` на хосте запускает `update.sh`: образ агента из GHCR или
сборка из присланных исходников, замена образа в compose и перезапуск только агента. Агенту
доступ к Docker не даётся, compose и образ wg-easy не меняются. Итог (`update/status`) агент
отдаёт в `/health`, панель показывает его в карточке ноды; при неудаче — повтор через 30 минут.

## Блокировка торрентов

Всегда включена, настройки нет. Агент ноды ставит правила iptables в цепочку FORWARD сетевого
namespace wg-easy (весь трафик клиентов в обе стороны) и обновляет их вместе с лимитами скорости.
Блокировка только по сигнатурам BitTorrent в содержимом пакетов: рукопожатие пиров, запросы
к HTTP- и UDP-трекерам, DHT. Порты и число соединений не ограничиваются — обычный трафик
с любыми портами не страдает. Зашифрованный торрент сигнатур не содержит и без DPI не
распознаётся. Состояние и число отброшенных пакетов видны в карточке ноды.

## API

Интерфейс работает только через `/api/*` panel-api.

| Метод и путь | Что делает |
|---|---|
| `GET /api/clients` | клиенты: IP, состояние, срок, группа, заметка, лимит, трафик и handshake по нодам |
| `POST /api/clients` | создать на всех нодах: `{name, ip?, expiresAt?, group?, note?, limit?}` |
| `PATCH /api/clients/{id}` | изменить `{name?, ip?, enabled?, expiresAt?, group?, note?}` |
| `DELETE /api/clients/{id}` | удалить (профили на недоступных нодах дочистит синхронизация) |
| `PUT` / `DELETE /api/clients/{id}/limit` | лимит скорости `{down, up}` Мбит/с — на всех нодах |
| `GET /api/clients/{id}/config`, `/qr.svg` | конфиг и QR профиля (`?node=` — нода) |
| `POST /api/clients/{id}/telegram` | конфиг и QR администратору в Telegram |
| `GET /api/stats`, `/api/traffic/history`, `/api/traffic/usage`; `DELETE /api/traffic` | дашборд, сброс статистики |
| `GET` / `PUT /api/telegram`, `POST /api/telegram/test` | уведомления; токен бота наружу не отдаётся |

Уведомления о действиях с клиентами (создан — с конфигом и QR, удалён, включён/отключён, лимит)
отправляет сервер по настройкам событий, а не браузер.
