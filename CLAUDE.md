# Tunnelwright

Коммерческий VPN-сервис на AmneziaWG. Сейчас — панель управления несколькими VPN-нодами:
пользователь → его устройства (один IP на всех нодах) → профили на каждой ноде.
Дальше — аккаунты клиентов, оплата, клиентский бот, веб-кабинет, затем свои приложения
для Android и Windows.

- Как устроено сейчас — [docs/architecture.md](docs/architecture.md).
- Принятые решения, целевая архитектура и порядок работ — [docs/roadmap.md](docs/roadmap.md).
  Читай перед любой заметной задачей; новое решение — запиши туда.

## Язык

Интерфейс, документация, комментарии, docstring-и, сообщения коммитов и ответы — **на русском**.
Идентификаторы в коде — на английском.

## Структура

```
panel/      panel-api: Python 3.14, FastAPI, SQLite. app/routers/* — HTTP, app/*.py — логика, tests/
node/       node-agent: FastAPI, адаптер к wg-easy (будет заменён на awg напрямую), tc, iptables, метрики
web/        админка: React 19 + Vite, чистый JS, nginx с TLS. App.jsx — монолит, разбивается по страницам
installer/  установщик сервера (bash), шаблон docker-compose
host/       команды хоста: tunnelwright, продление сертификата, watchdog
deploy/     стеки Portainer: основной и тестовый (ветка dev, образы :dev)
docs/       архитектура и направление развития
```

## Команды

```bash
cd panel && python -m pytest -q                         # тесты panel-api
cd node && python -m pytest -q tests                    # тесты агента
cd web && npm ci && npm run lint && npm run build       # фронтенд
```

CI (`.github/workflows/ci.yml`) на каждый push: `bash -n` и ShellCheck скриптов, тесты обоих
Python-сервисов, lint и сборка web, сборка трёх образов. Перед коммитом прогоняй то, что затронуто.

## Ветки и релизы

- `dev` — разработка (образы `:dev`, тестовый стек Portainer), `rc` — кандидат, `main` — релизы.
- Задачи — в отдельных ветках от `dev`, слияние в `dev`.
- Релиз: `VERSION` и `version` в `web/package.json` → тег `vX.Y.Z` на `main`. Тег обязан совпадать с `VERSION`.
- Сообщения коммитов — одна короткая строка по-русски, что изменилось:
  «Подсеть устройств 10.8.0.0/20 вместо /24», «Пользователи и устройства: конфиги создаются под пользователем».

## Инварианты — не нарушать

- **Панель — источник правды.** Ноды выполняют; синхронизация (`clients.sync_all`) приводит ноды
  к состоянию панели. Не меняй состояние ноды в обход панели.
- **Рабочие конфиги клиентов не ломаются.** Ключи, IP и адрес ноды существующих устройств меняются
  только явным действием или миграцией, сохраняющей их. Это касается и перехода с wg-easy.
- **Миграции БД — только добавлением** нового элемента в конец `MIGRATIONS` в `panel/app/db.py`.
  Старые миграции не редактируются. Миграция должна сохранять данные (см. миграции 8 и 10).
- **Секреты не уходят в браузер и логи:** токены нод и ботов, ключи устройств, пароли, данные платёжных систем.
- **Время в БД — UTC.** Часовой пояс панели — только для отображения и границ суток/месяца.
- Наружу открыты только порт панели (HTTPS) и UDP-порты VPN.

## Правила с расчётом на будущее

- Бизнес-логика — в сервисных модулях `panel/app/*.py`, роутеры тонкие. Админка, кабинет,
  клиентский бот, webhook-и и будущий `/api/client/v1` вызывают одни и те же функции.
- Новое про устройства и ключи проектируется под «ключ создаётся на устройстве, один на все ноды»;
  старый режим (свой ключ на каждой ноде) поддерживается для перенесённых устройств.
- Два API в одном процессе: админский `/api/*` и клиентский `/api/client/v1` (кабинет, позже приложения).
  Клиентский версионируется в пути, внутри версии — только совместимые изменения. Сессии админов
  (`security.py`) и клиентов (`client_auth.py`) не пересекаются. Кабинет ходит только в клиентский API.
- Деньги — целые числа в минимальных единицах валюты. Статус оплаты — только от провайдера
  (webhook или запрос), webhook-и идемпотентны по `(провайдер, внешний id)`.
- Не завязывайся на wg-easy в новом коде: всё, что касается туннеля, — через агент ноды и его API.

## Стиль кода

- Пиши как окружающий код: короткие модули, docstring модуля объясняет модель и зачем она такая,
  комментарии — про «почему», а не «что».
- Python: стандартная библиотека и уже подключённые зависимости (`requirements.txt` с точными версиями);
  новую зависимость — только по необходимости и с закреплённой версией.
- SQL — простой, без лишних особенностей SQLite, чтобы переход на Postgres оставался возможным.
- Ноды в тестах — фикстура `cluster` из `panel/tests/fakes.py`; новое поведение покрывается тестом.
- web: цвета только через CSS-переменные из `web/src/theme/tokens.css`, обе темы равноправны.
